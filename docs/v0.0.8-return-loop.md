# TinyWorld v0.0.8 return-loop test

v0.0.8 adds a bounded reason to return to the same village without changing
the original TinyWorld life loop. The fountain, Courier job, garden, and
woods/cliffs/sea boundary remain the source of rewards; the new layer records
successful actions into a small daily route and a small weekly route.

## Contract

- The profile schema is version 6. Profiles from v0.0.5-v0.0.7 receive empty
  route fields through the existing normalisation path.
- Daily routes use UTC calendar days. Each day selects three tasks from a
  deterministic rotation. The fountain is always one task; the other two are
  selected from Courier delivery, garden harvest, and completing the boundary
  route.
- Weekly routes use a deterministic seven-day UTC window and select three
  tasks from their own rotation. The current route key is stored in the
  profile, so a new period starts with an empty mask rather than inheriting
  stale progress.
- A successful task can be recorded only once in its period. Completing all
  three tasks grants one bounded reward: `+75 coins, +25 XP` for the daily
  route and `+250 coins, +100 XP` for the weekly route. Repeating a task or
  touching a completed route cannot grant another route reward.
- The HUD exposes `Return loop: today x/3 | week y/3`. The server remains
  authoritative for task completion, masks, rewards, and persistence.

## Action mapping

| Player action | Route task | When it counts |
| --- | --- | --- |
| Claim the village fountain | `daily_reward` | The fountain claim succeeds for the UTC day |
| Complete a Courier delivery | `courier_delivery` | The parcel is delivered at the Village Shop |
| Harvest a Carrot | `garden_harvest` | The garden harvest succeeds |
| Claim the Boundary Explorer route | `boundary_route` | All three boundary landmarks were visited and the board claim succeeds |

The action services save successful profile mutations, including the garden
and Courier paths that previously had no explicit save call. Route completion
rewards are applied before the save is queued, so the coalescing profile queue
persists the complete state as one update.

## Local verification

Run from the repository root:

```powershell
luau tests/run.luau
luau-analyze src/shared/*.luau tests/*.luau
luau-analyze src/server/*.luau src/client/*.luau
powershell -NoProfile -ExecutionPolicy Bypass -File tests/verify-roblox-materials.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/verify-profile-store.ps1
rojo build default.project.json -o .worktrees\tinyworld-v0.0.8.rbxlx
git diff --check
```

The deterministic suite covers period rotation, migration, duplicate-task
protection, completion rewards, and reward caps. The Roblox material and
profile hardening guards protect the earlier v0.0.5-v0.0.7 contracts. A Rojo
build proves the new shared/server/client files assemble into a place; it is
not a substitute for a live Play session.

## Runtime and family evidence boundary

On 2026-08-09, the authenticated Rojo-synced Studio place passed a single
client route: the HUD moved from `today 0/3 | week 0/3` to `1/3 | 1/3` after
the fountain, `2/3 | 1/3` after Courier delivery, and `3/3 | 2/3` after a
Carrot harvest. Completing the woods/cliffs/sea boundary and claiming the
Explorer Board produced `today 3/3 | week 3/3`, the daily and weekly bounded
route messages, and the expected profile changes. Repeating the fountain
claim left coins and route counts unchanged and showed the existing daily
duplicate guard. The stopped-session Output pane showed the command-bar test
inputs and Rojo disconnect only; no red source/runtime exception was visible.

Studio API Services and a published Dev experience remain dependencies for
DataStore-backed persistence. This single Studio client proves route state
integration and the save-queue path, but two clients and the family session
are still required to prove social comprehension, concurrency, and
retention. Those claims are not inferred from the single-client run.

The v0.0.8 release stays within the north star: a child can choose a life,
make a home, do useful work, explore the village edge, and have a fair reason
to come back. It adds no Robux products, ads, pay-to-win progression, or new
portal world.
