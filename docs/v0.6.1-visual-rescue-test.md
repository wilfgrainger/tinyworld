# TinyWorld v0.6.1 Visual Rescue Studio route

**Purpose:** prove the exact v0.6.1 candidate looks and plays like the intended TinyWorld visual baseline. This is observed evidence, not a source checklist.

## Before testing

Record:

- release: `0.6.1 Visual Rescue`;
- branch/PR;
- exact source commit SHA;
- exact Rojo artifact filename/SHA when testing a built artifact;
- Studio version;
- test experience/place;
- viewport/device simulation;
- graphics quality;
- profile state: fresh or named existing DEV profile.

Use the DEV DataStore namespace only. Do not point Studio testing at LIVE data.

Review Output before starting. Any unresolved critical runtime error blocks the route.

## Evidence result values

Use only:

- `PASS`: observed and met the stated check;
- `FAIL`: observed and did not meet the check;
- `BLOCKED`: could not execute because a named dependency/tool failed;
- `NOT RUN`: not attempted yet.

Do not infer one row from another.

## 1. Character baseline

1. Spawn the player and wait for character load/onboarding completion.
2. Capture front three-quarter and side views at normal gameplay zoom.
3. Confirm:
   - no rectangular TinyWorld hair block is attached to the head;
   - no cuboid TinyWorld shoe block is attached to the feet;
   - normal Roblox clothing/accessories remain intact;
   - TinyWorld has not made the avatar visibly worse than the normal Roblox baseline.

Evidence file: `docs/quality/benchmarks/v0.6.1/01-character-front.png`.

## 2. Normal HUD

1. Stand in an open village area with no modal open.
2. Capture the full viewport.
3. Confirm:
   - compact coin/level/task status occupies a small top-left area;
   - no full-width top website-style navigation/status bar exists;
   - one compact `Journal / Home / Style` navigation surface is present;
   - no permanent `My World` telemetry/status dashboard exists;
   - the 3D world is visually dominant.

Evidence file: `02-normal-hud.png`.

## 3. Village-centre labels-off recognition

Hide/avoid explanatory prompts where practical, then stand at a normal approach position to the village centre.

Without reading floating system labels, identify:

- Town Hall;
- Village Shop;
- Home Store;
- Courier Depot;
- daily fountain;
- jobs/profession board.

Fail any destination whose category can only be inferred from a floating paragraph/system label.

Evidence file: `03-village-centre-labels-off.png`.

## 4. Town Hall

Approach from the normal route and capture a three-quarter exterior view.

Pass cues:

- civic building silhouette;
- readable entrance/steps;
- framed windows/roof hierarchy;
- clock/tower/bell cue;
- jobs board/community contribution props read as physical objects rather than floating UI.

Evidence file: `04-town-hall.png`.

## 5. Village Shop

Approach from the normal route.

Pass cues:

- clearly a general/ordinary shop before reading its proper name;
- shopfront/window/awning/counter or visible stock cues;
- physically distinct from Home Store.

Evidence file: `05-village-shop.png`.

## 6. Home Store

Approach from the normal route.

Pass cues:

- homewares/furniture identity is physically obvious;
- display furniture/showroom/counter language is visible;
- supply/style/gallery actions use local prompts/panels rather than permanent floating information walls.

Evidence file: `06-home-store.png`.

## 7. Courier Depot

Approach from the normal route.

Pass cues:

- parcels/sorting/loading/work-delivery context is visible;
- depot identity does not depend on a floating paragraph;
- available parcel/pickup interaction is physically local.

Evidence file: `07-courier-depot.png`.

## 8. Daily fountain

Capture the fountain at player height.

Pass cues:

- basin;
- pedestal/spout/upper feature;
- visible water;
- plaza/landmark context;
- daily reward is a contextual interaction, not a glowing sphere plus explanation wall.

Evidence file: `08-daily-fountain.png`.

## 9. Starter-home exterior

Walk to the assigned home without using a floating `HOME GATE` explanation.

Pass cues:

- home ownership/location is understandable;
- pitched/characterful roof silhouette;
- framed windows;
- proper door/porch/step relationship;
- small asymmetry/dressing;
- access/privacy interactions are local to gate/door objects.

Evidence file: `09-starter-home-exterior.png`.

Identify without explanatory labels:

- wardrobe;
- sofa/living area;
- cooker/sink/kitchen area;
- bath/shower/bathroom cue;
- table/chairs;
- storage;
- lamp;

Evidence file: `10-starter-home-interior.png`.

## 11. Giant Kitchen entrance

Capture the approach/entrance only for v0.6.1 visual baseline.

Pass:

- entrance identity does not require a black information wall.

## 12. Moonlit Meadow entrance

Repeat the portal-entrance check for Moonlit Meadow.

Evidence file: `12-moonlit-meadow-entrance.png`.

## 13. Golden ordinary-life route

Run without developer coaching:

`spawn -> understand HUD -> identify home -> enter home -> use a recognisable object -> walk to Courier Depot -> collect a visible parcel -> complete delivery -> receive coins -> identify Home Store -> buy one furniture item -> place it -> rejoin -> confirm continuity`

For every step record:

- action;
- expected visible outcome;
- PASS/FAIL/BLOCKED;
- confusion or extra explanation required;
- critical Output error, if any.

A technically successful server mutation still fails this route if the player cannot understand what happened visually.

## 14. Phone evidence

On the agreed phone/device or Studio device emulation plus real device when available:

- portrait screenshot;
- landscape screenshot;
- HUD does not dominate/clip;
- `Journal / Home / Style` remains reachable;
- modal close/save/place controls remain reachable;
- touch targets remain at least 44x44 effective pixels;
- record FPS, memory and useful-spawn time against current budgets.

## 15. Controller evidence

Using controller/gamepad:

- navigate/open Journal;
- open/close Home;
- open/close Style;
- enter furniture placement when available;
- rotate/confirm/cancel;
- verify no focus trap and a sensible first focus target on modal open.

## 16. Final Output review

After the full route:

- inspect Roblox Output;
- record any warnings/errors attributable to TinyWorld;
- unresolved critical errors block PASS.
