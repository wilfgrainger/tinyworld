# TinyWorld v0.6.0 Codex Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans with test-driven-development, receiving-code-review, requesting-code-review, verification-before-completion, and finishing-a-development-branch.

**Goal:** Resolve every fresh Codex finding on PR #5 without weakening the v0.6.0 target-state contract, then leave zero unresolved review threads and a green exact-head build.

**Architecture:** Preserve the current no-framework Roblox architecture. Fix compatibility at the shared-rule boundary, keep all economy/trade/home mutations server-authoritative, and add small pure helpers where runtime behavior needs deterministic tests. Client changes may predict UI state but never become authoritative.

**Tech Stack:** Luau, Roblox server/client runtime, Rojo, GitHub Actions, StyLua, Luau 0.732.

## Global Constraints

- Branch: `docs/target-state-v1`; do not merge until all review threads are resolved and exact-head CI is green.
- Profile schema remains `11` and must preserve v10 compatibility during the transition.
- No fake Roblox asset/product/place IDs or credentials.
- High-value unique trading stays disabled in v0.6.0.
- Studio/device/published evidence remains PENDING unless genuinely exercised.
- Every behavior fix gets a failing regression test first where a pure/shared rule can express it.
