# v0.9.0 Production Beta

**Status:** future evidence/configuration release.

v0.9.0 should turn the v0.6-v0.8 product into a measured launch candidate. It is not the moment to add a new gameplay architecture or relax the v0.6.1 visual-evidence discipline.

## Goals

- configure a real private DEV universe/place only after explicit human approval;
- store DEV/LIVE publishing credentials outside source control with least privilege/environment protection;
- publish the exact traceable candidate artifact to DEV;
- run one-player, multi-client, phone/controller, visual and performance evidence routes;
- compare key player-facing views against the current committed visual benchmarks and active visual-quality contract;
- observe the documented AnalyticsService funnel in the published DEV experience;
- tune StreamingEnabled/content budgets from measured world/device evidence where required;
- fault-test profile lease/load/save/migration/rejoin/shutdown routes;
- prove durable trade journal/recovery semantics before considering unique/high-value trading;
- complete accessibility, safety/social and family playtesting;
- verify production asset provenance and runtime budgets.

## Gates

- no unobserved runtime/device/visual row marked PASS;
- no player-facing release candidate accepted merely because source/CI is green;
- no regression to primitive avatar add-ons, floating ordinary-world information walls or telemetry-heavy normal HUD;
- no DEV credential exposed to untrusted PR execution;
- DEV and LIVE DataStore namespaces remain distinct;
- a failed migration/save/load continues to fail closed;
- candidate SHA/artifact hash are recorded for every published test;
- high-value trade remains disabled unless recovery evidence passes.

## Output

A launch-candidate artifact with complete automated, Studio, multiplayer, visual, device and published-DEV evidence, ready for explicit human promotion approval rather than an automatic LIVE release.
