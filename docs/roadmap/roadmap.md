# Product roadmap

The roadmap is dependency-gated, not a promise of dates. A release advances only when its acceptance record distinguishes automated source/build evidence from Studio, multiplayer, published-place and device evidence.

| Release | Primary purpose | Player-visible outcome |
| --- | --- | --- |
| v0.5.1 | Physical-world hardening and save triggers | Historical baseline |
| v0.5.2 | Village Soul | Historical sixteen-home village/presentation baseline |
| v0.5.3 | Production Engineering Foundation | Historical credential-free Rojo/release-evidence baseline |
| v0.6.0 | Target-State Consolidation | Merged scalable home/content/data/security/UI/world foundation |
| **v0.6.1** | **Visual Rescue** | Remove prototype visual language, rebuild hero readability, compact the HUD and prove one golden ordinary-life route |
| v0.7.0 | Village Life | Deeper destinations, careers, routines and shared village activities on the v0.6.1 visual baseline |
| v0.8.0 | Impossible Worlds | Deeper authored portal mechanics/secrets/home payoffs |
| v0.9.0 | Production Beta | Runtime security/performance/device/analytics/DEV publishing evidence at launch-candidate quality |
| v1.0.0 | Launch | Coherent persistent life sandbox with evidenced launch quality |

## Current release

[v0.6.1 Visual Rescue](v0.6.1-visual-rescue.md) is the active corrective release.

The first observed merged v0.6.0 screenshots showed a mismatch between the written visual-quality contract and the rendered game: primitive avatar add-ons, floating information walls, overly dominant HUD chrome and hero destinations still reading as fallback geometry. v0.6.1 fixes that before deeper Village Life work proceeds.

The current product north star remains [TinyWorld v1 Target State](../product/target-state-v1.md).

## Visual direction decision

The release uses broad qualities rather than copied expression:

- Brookhaven-level readability for ordinary world navigation;
- Toca-style tactile warmth and object clarity;
- Ready Player One-style wonder and contrast for impossible worlds;
- original TinyWorld characters, props, buildings, layouts, UI and names.

Normal village life should remain grounded/readable. Portal worlds carry the strongest scale break, glow and fantasy.

## Release discipline after v0.6.0

v0.6.0 was intentionally broad. v0.6.1 reinstates focused playable slices and adds a stronger visual-evidence rule:

- player-facing PRs may keep required Studio/device rows NOT RUN while draft;
- those rows block merge-ready status;
- FAIL is useful evidence and creates bounded corrective work;
- source/CI may not be used as a substitute for observed visual quality.

After v0.6.1:

- v0.7.0 deepens everyday village life rather than adding a new architecture;
- v0.8.0 deepens impossible worlds rather than adding many shallow portals;
- v0.9.0 prioritises measured security/performance/accessibility/DEV evidence;
- v1.0.0 freezes major system scope and focuses on polish, balancing, safety, device evidence, rollback and launch metadata.

## Deferred external gates

The repository deliberately does not contain production credentials, fake IDs or automated LIVE publishing. DEV/LIVE configuration and same-artifact promotion occur only after explicit approval and recorded runtime/device evidence.
