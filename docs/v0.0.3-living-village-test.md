# TinyWorld v0.0.3 living-village test

This is the code-and-Rojo acceptance guide for the `feat/v0.0.3-living-village` branch. It preserves the v0.01/v0.0.2 route and adds a capacity-aware village perimeter.

## What v0.0.3 must show

- The original four plot coordinates still exist, and additional plots are generated from the configured Roblox server capacity rather than a hard-coded four-plot list.
- The village has one stable `Ground` floor, a visible woods/cliffs/sea boundary, and the boundary is built once per server.
- The HUD title identifies v0.0.3 and shows `Explore: x/3 boundary landmarks` plus completed route count.
- The Woodland Trail, Cliff Lookout, and Sea Dock each accept one server-authoritative visit per UTC day.
- The Explorer Board refuses an incomplete route, grants `+250 coins` and `+100 XP` once all three landmarks are visited, and refuses a second claim that day.
- A stop/rejoin preserves the new route state and the existing profile fields.

## Studio route

1. Start `rojo serve` from this checkout and connect the Studio Rojo plugin to `localhost:34872`.
2. Stop any old Play session, sync the current branch, and press Play.
3. Confirm the HUD says `TINYWORLD | v0.0.3 LIVING VILLAGE`, the initial plot/home still works, and the Output pane has no red errors.
4. Walk outward from the village and verify the three readable boundary landmarks: `WOODLAND TRAIL`, `CLIFF LOOKOUT`, and `SEA DOCK`. The village should visibly transition from ground to sand, rock/basalt cliffs, trees, and sea instead of ending at a floating square.
5. Return to the `BOUNDARY EXPLORER` board and press `E` before visiting all three. Confirm the incomplete-route message and no coin/XP change.
6. Visit all three landmarks, checking the HUD progresses from `0/3` to `3/3`. Return to the board and press `E`. Confirm the route reward and `Routes 1`.
7. Press `E` at the board again. Confirm the same-day duplicate message and no second reward.
8. Run the existing v0.01/v0.0.2 smoke route: onboarding or saved identity, fountain, garden, Courier pickup/delivery, Tiny Bike, home/privacy, portal, and trade regression as time permits.
9. Stop and rejoin. Confirm the identity, progression, boundary completion count, and current-day route protection persist.

## Capacity check

The pure layout test covers server capacities 1, 4, 8, 16, 32, and 50, with a minimum of four plots. In Studio, use the configured multi-client capacity when available and verify that plots remain separate and the single boundary remains outside the outermost plot. The boundary grows with the outer plot ring; it is not copied once per player.

## Computer Use evidence note

Computer Use may use runtime-only teleportation or temporary prompt hold-duration changes to make a deterministic route observable when the automation layer cannot reliably hold Roblox's normal `E` prompt or move the avatar. Those aids are test-session state only: they must never be saved to the repository, the published place, or player profiles. Ordinary keyboard movement and prompt timing remain a real-device acceptance check.

## Deliberately separate release gates

This slice does not claim public release readiness, production DataStore safety, family/device approval, real two-player trade proof, or live monetization. Keep the Dev experience limited to named playtesters until those gates are separately evidenced.
