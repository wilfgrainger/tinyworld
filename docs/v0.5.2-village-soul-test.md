# v0.5.2 Village Soul test route

## Release rule

Run this route against one named commit and record `Pass`, `Fail`, `Blocked`, or `Not run` for every check. Local source evidence does not count as Studio evidence, Studio evidence does not count as published-place evidence, and desktop evidence does not count as device evidence. Do not mark a higher evidence class from a lower one.

The v0.5.2 premium-feel quality gate is a craft gate, not monetisation or another gameplay system. It requires authored silhouettes, quality materials, composed lighting, tactile feedback, restrained UI, no arbitrary coloured cubes or telemetry walls, and a labels-off child-recognition test. One failed check blocks release acceptance.

## Exact Studio setup

1. Check out the commit recorded above. Run `rojo serve` from the repository root.
2. Open a private TinyWorld test place in Roblox Studio, connect the Rojo plugin to `default.project.json`, and confirm `TinyWorld` appears under ReplicatedStorage, ServerScriptService, and StarterPlayerScripts.
3. For persistence checks only, enable **Game Settings → Security → Enable Studio Access to API Services** on this private test place. Never use a production place for destructive profile experiments.
4. Open **View → Output**, clear existing entries, and keep Output visible for the whole route.
5. Use an account with a fresh profile for Onboarding. Use two test accounts with disposable inventory for Trade. Do not infer a fresh profile after a DataStore read failure; loading must fail closed.
6. Press **Play** for the one-player route. Use **Test → Start** with two players for the two-client route. Stop and record `Blocked` if profile loading fails.

## One-player Studio route

1. **Onboarding** — On a fresh profile, verify avatar and Meadow/Harbor/Sunset outfit choices are visual cards with silhouette, colour, and plain-language fantasy copy. Select values, finish once, and capture the completed first-play view. Fail if movement is left blocked, the choice is text-only, or the server rejects a displayed valid option.
2. **Compact HUD** — Verify normal play shows coins, level progress, one task, Journal access, contextual prompts, and short toasts only. Fail if raw replicated fields or a permanent telemetry panel/telemetry wall appears.
3. **Journal** — Open Today, Bag, Home, Careers, and Collection. Verify each uses friendly player language and that closing it returns to unobstructed play. Fail if database field names or raw diagnostics appear outside Studio-only debug UI.
4. **Neighbourhood walk** — Walk the village centre, Meadow Lane, Harbour Row, Woodland Rise, and Orchard End. Capture one wide centre view and one view per neighbourhood. Verify the centre is not a symmetric grid, landmarks remain visible, routes remain traversable, and stream/bridge, harbour clutter, woodland canopy, and orchard/nursery identity are distinct.
5. **Ambient life** — Observe at least one chimney smoke emitter, warm window/light, water highlight, foliage hook, bird hook, and butterfly hook. In Explorer, select `Workspace.TinyWorldGenerated.AmbientLife`; verify `TinyWorldAmbientEffectCount` is no greater than 24, `TinyWorldAmbientEmitterCount` is no greater than 3, and `TinyWorldAmbientScope` is `world`. Rejoin once and verify seeded placement is unchanged. Fail on per-player duplication, runaway particles, route-obscuring effects, or unreadable mobile-scale clutter.
6. **Labels-off child-recognition test** — During Play, open the Command Bar and run:

   ```luau
   for _, item in workspace.TinyWorldGenerated:GetDescendants() do
       if item:IsA("BillboardGui") or item:IsA("ProximityPrompt") then
           item.Enabled = false
       end
   end
   ```

   Without showing this checklist or coaching, ask one child aged 7–12 to point out a home, Town Hall, courier depot, village/home shop, transport workshop, market, bicycle, and boat. Accept clear child-language synonyms such as “post office” for courier depot. Record each answer separately. Pass only if all eight categories are recognized from the world view; fail if labels, arbitrary colour coding, telemetry, or coaching are needed. Restore labels by stopping and starting Play.
7. **Hero-home interactions** — Enter the assigned starter/Cosy home. Identify bedroom, kitchen, living area, bathroom, storage, and garden from their objects. Use bed, kitchen, wardrobe, desk, item chest, light, sink, cooker, and door/lid actions where prompts are available. Verify tactile feedback: bounded light, motion, object-state, sound, or a short toast follows input; fail if only text or a raw value changes.
8. **Garden and privacy** — Plant/water/harvest a garden bed through its visible bed and use the front-door bell/gate sign to cycle privacy. Verify the object state and friendly feedback update while server ownership rules remain enforced.
9. **Bike and boat** — At the transport workshop, buy/toggle or mount the Tiny Bike as account state permits; verify wheels, frame, seat, basket, handlebars, and bounded motion feedback. At the Sea Dock, buy/summon and board the Tiny Boat as account state permits; verify hull, bow, seat, tiller, mast/sail, and bounded wake/flag feedback, then return to the dock.
10. **Portal** — Enter the Giant Kitchen or Moonlit Meadow portal, collect one required object, and return to the village. Verify the destination, collectible, and return portal read physically and that progression changes only through the authoritative prompt.
11. **Trade** — Restart with two Studio clients. Each client joins a different physical market stool/tray side, chooses an owned disposable offer, and confirms. Verify both trays/ledgers communicate state, changing an offer invalidates prior confirmation, and completion is atomic for both players.
12. **Persistence** — In the API-enabled private test place, make one authoritative change, wait for the save state to report success, leave, rejoin, and verify the saved value returns. Fail closed on DataStore read failure; never accept replacement default data as persistence evidence.
13. **Output review** — Filter Output for `Error`, infinite yield, DataStore failure, budget failure, and stack traces. Record every entry and disposition. Pass only with no unexplained release-blocking errors or warnings.

## Premium-feel quality gate observation

Complete this table from the Studio route, not from source inspection alone:

| Check | Pass evidence | Fail condition | Result/link |
| --- | --- | --- | --- |
| Authored silhouettes | Labels-off recognitions and screenshots show category-specific shapes. | A sign, generic block, or colour is needed. | |
| Quality materials | Contextual wood, brick, slate, glass, fabric, metal, water, and foliage are visible. | Anonymous or arbitrary treatment dominates a primary object. | |
| Composed lighting | Daylight, shadow, warm windows, and restrained glow preserve hierarchy. | Flat, dark, or blown neon hides routes or silhouettes. | |
| Tactile feedback | Recorded interactions produce bounded motion, light, state, sound, or short toast. | Only text or telemetry changes. | |
| Restrained UI | Compact HUD, journal, prompts, and short toasts leave the world dominant. | Telemetry walls or raw fields dominate normal play. | |
| No arbitrary coloured cubes | Every player-facing object has a recognizable art and physical role. | A coloured cube substitutes for an object, verb, or destination. | |
| Labels-off child-recognition test | All eight required categories are recorded correctly without coaching. | Any category needs labels, telemetry, arbitrary colour, or coaching. | |
