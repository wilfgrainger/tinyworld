# TinyWorld v0.5.1 physical-world and state-hardening test

v0.5.1 is a small hardening release on top of the v0.5.0 traversal slice. It
makes the physical-affordance rule explicit in shared code and in the generated
world: an item is never proven by a profile count alone. It must have a named
world representation or an immediate named popup. The release also closes two
save-wiring gaps found during the audit: home upgrades and Village Fund
contributions now enter the coalescing ProfileStore queue.

No new currency, paid gate, inventory item, combat system, or progression
advantage is introduced.


The expected pure-suite line is `TinyWorld tests passed: 24 specs`. A clean
source gate still proves source and assembly only; it does not substitute for a
live Studio run or a reopened published place.

## Studio route

1. Run `rojo serve` from the repository root and connect the authenticated
   Studio plugin to `localhost:34872`.
2. Press Play and confirm the HUD reads
   `TINYWORLD | v0.5.1 PHYSICAL WORLD`.
3. Claim the fountain reward or harvest a ready carrot. Confirm the popup names
   `Carrot`, then inspect the physical Item Chest and its labelled carrot object.
4. Collect a Meadow Seed, Seashell, and Wood Token from their visible world
   pickups. Confirm each pickup exists before interaction and each result popup
   names the item.
5. Complete a portal world or trade. Confirm the collectible/offer exists at a
   physical world object or Trading Post surface, the result popup names what
   was received, and the Item Chest refreshes afterward.
6. Earn the Home Charm ingredients and use the physical Home Garden prompt.
   Confirm the home gains the labelled `HOME CHARM` display, blooming garden
   dressing, and the `Home Charm added` popup.
7. Upgrade the home and contribute to the Village Fund. Confirm the house/sign
   changes immediately and the popup is present.
8. Stop and rejoin. Confirm the upgraded house, Home Charm, inventory chest,
   contribution, bike, and boat state remain consistent with the saved profile.
9. Keep Output visible. Any red source/runtime exception is a failure. A Rojo
   disconnect or known Studio DataStore queue/competing-session warning remains
   a separate test-environment dependency.

## Evidence boundary

The source gate proves that all current item paths have a shared physical-world
contract, concrete world markers, chest refresh wiring, named reward messages,
and save queue calls for the audited mutations. It does not prove normal
keyboard movement, two-player trade, device comprehension, live published-place
parity, or production scale. Those remain separate evidence gates.
