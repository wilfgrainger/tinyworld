# TinyWorld v0.1.0 invited-alpha test

v0.1.0 is the first invited-alpha operations slice. It does not add a new
portal world or monetisation. It makes the existing TinyWorld life safer to
observe in a small family cohort: onboarding state, profile save pressure,
session recovery requirements, and aggregate cohort health are explicit.

Read the [v0.1.0 design](superpowers/specs/2026-08-09-tinyworld-v0.1.0-invited-alpha-design.md)
before treating any diagnostic as evidence of a published or production system.

## Contract

- The player-facing candidate is labelled `TODAY / INVITED ALPHA` with a
  readable `TINYWORLD | v0.1.0 ALPHA` title.
- The generated world root exposes aggregate-only attributes for the invited
  alpha channel, recommended cohort size (8), active/ready/setup/saving/
  recovery counts, queue depth, cohort state, and last observer sync.
- Each loaded player receives release/channel/health attributes. A healthy
  player is `ready`; a new player is `setup`; a profile with queued or retrying
  writes is `saving`; a failed or lost session is `recovery-required`.
- A recovery transition produces one safe rejoin message and never silently
  overwrites a competing profile session.
- These attributes are operational evidence only. Roblox Audience, Playtesters
  access, Creator Dashboard analytics, two-client behavior, and family/device
  comprehension remain separate gates.

## Studio route

With the current source connected through Rojo:

1. Start Play and confirm the HUD eyebrow reads `TODAY / INVITED ALPHA` and
   the title reads `TINYWORLD | v0.1.0 ALPHA`. For a fresh profile, confirm the
   welcome setup still asks for display name, Boy/Girl, and one of the three
   free starter outfits.
2. Open the generated `TinyWorldGenerated` root in Explorer and inspect its
   attributes. Confirm `TinyWorldAlphaChannel` is `INVITED_ALPHA`, the
   recommended cohort is `8`, and the initial health is consistent with the
   profile state.
3. Complete onboarding or rejoin with the existing profile. Confirm the
   player health becomes `ready` when the save state is clean and the session
   is active. Do not alter source or profile data through the Studio command
   bar to manufacture a green result.
4. Run one ordinary return-loop action and one v0.0.9 home/social action. The
   operational attributes should continue to update while the gameplay route
   remains intact.
5. Stop Play and inspect Output. Separate normal test-environment DataStore
   queue/competing-session warnings from red source/runtime exceptions. Record
   the exact message rather than deleting or hiding it.

## Runtime evidence captured 2026-08-09

- The current Rojo-synced authenticated Studio session showed the readable
  `TODAY / INVITED ALPHA • STORYBOOK` eyebrow and `TINYWORLD | v0.1.0 ALPHA`
  title while the existing persisted player route remained playable.
- A command-bar diagnostic read the generated world attributes as release
  `0.1.0`, channel `INVITED_ALPHA`, recommended cohort `8`, health `ready`,
  active players `1`, and queue depth `0`. The player health was `ready` with
  `recovery-required` false.
- The stopped session showed only the Rojo disconnect line in Output and no
  red server/client source exception. This is single-client Studio evidence;
  it does not prove DataStore fault injection, two-client behavior, or a
  published-place/family-device result.

## Recovery and cohort evidence

The deterministic suite covers the health contract. A normal Studio session
proves attribute wiring and lifecycle observation only. The following still
require explicit evidence:

- a real transient DataStore failure and recovery attempt;
- a competing session across two authenticated clients or servers;
- two-client party/privacy/trade behavior from v0.0.9;
- the Roblox-published place reopened from the target experience;
- family/device comprehension and whether the game feels worth returning to.

The recommended first invited-alpha cohort is no more than eight players in a
coordinated session. That recommendation is a safety and observation boundary,
not a measured concurrency ceiling. Children receive Play access only; they do
not receive Edit access, repository credentials, API keys, or operator
diagnostics as a condition of play.

## North-star guardrail

TinyWorld remains a cosy, social, expressive world whose future creator income
must come from durable player value. v0.1.0 adds no Robux products, ads, paid
access, or progression advantage.
