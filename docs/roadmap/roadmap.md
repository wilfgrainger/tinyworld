# Product roadmap

The roadmap is dependency-gated, not a promise of dates. A release advances only when its acceptance record distinguishes automated source/build evidence from Studio, multiplayer, published-place and device evidence.

| Release | Primary purpose | Player-visible outcome |
| --- | --- | --- |
| v0.5.1 | Physical-world hardening and save triggers | Historical baseline |
| v0.5.2 | Village Soul | Historical sixteen-home village/presentation baseline |
| v0.5.3 | Production Engineering Foundation | Historical credential-free Rojo/release-evidence baseline |
| **v0.6.0** | **Target-State Consolidation** | Scalable home life, content/data/security/UI/world foundations in one release candidate |
| v0.7.0 | Village Life | Deeper destinations, careers, routines and shared village activities |
| v0.8.0 | Impossible Worlds | Deeper authored portal mechanics/secrets/home payoffs |
| v0.9.0 | Production Beta | Runtime security/performance/device/analytics/DEV publishing evidence at launch-candidate quality |
| v1.0.0 | Launch | Coherent persistent life sandbox with evidenced launch quality |

## Current release

[v0.6.0 Target-State Consolidation](v0.6.0-target-state-consolidation.md) is the active repository release candidate. It moves the profile to schema v11, establishes scalable content/home placement and applies the repository-side target-state blueprint without fabricating runtime/device/publishing evidence.

The current product north star is [TinyWorld v1 Target State](../product/target-state-v1.md).

## Release discipline after v0.6.0

v0.6.0 is intentionally broad because the user approved a one-PR consolidation of the complete upgrade blueprint. Future releases should return to narrower playable slices:

- v0.7.0 deepens everyday village life rather than adding a new architecture;
- v0.8.0 deepens impossible worlds rather than adding many shallow portals;
- v0.9.0 prioritises measured security/performance/accessibility/DEV evidence;
- v1.0.0 freezes major system scope and focuses on polish, balancing, safety, device evidence, rollback and launch metadata.

## Deferred external gates

The repository deliberately does not contain production credentials, fake IDs or automated LIVE publishing. DEV/LIVE configuration and same-artifact promotion occur only after explicit approval and recorded runtime/device evidence.
