# v0.6.3 documentation review

**Date:** 11 August 2026  
**Release:** v0.6.3 Production Art & World Craft  
**Purpose:** review TinyWorld's documentation authority before changing runtime code, and remove wording that allowed source-level visual intent to outrun rendered quality.

## Review method

The repository documentation index, repository-wide code/document search and linked historical records were reviewed in two classes:

1. **Durable/current contracts:** reviewed semantically and updated where version-specific language or visual ambiguity could influence current implementation.
2. **Historical release/spec/plan records:** reviewed for authority leakage/status ambiguity. Historical implementation decisions remain historical and are not rewritten as if they were current work.

This review does not treat a historical plan as evidence that its player-facing result passed.

## Findings

### F1 — visual contracts were stronger than the rendered result

**Severity: P0 product quality.**

`art-direction.md`, `village.md`, `homes.md` and `visual-quality-bar.md` already required pitched/characterful roofs, distinct civic silhouettes, real fountain geometry, no naked arbitrary glow, neighbourhood differentiation and labels-off recognisability.

The user-provided 11 August v0.6.2 Studio screenshots visibly fail several of those requirements:

- oversized slab roofs dominate hero buildings;
- windows read as bright cyan rectangles;
- ordinary lamps/reward cues use naked yellow glowing spheres;
- the elevated village reads as a flat green/grid test map;
- large open grass/paved spaces lack authored spatial hierarchy;
- civic/home geometry remains primitive enough to read as generated/test construction.

**Action:** v0.6.3 introduces an explicit production-art release, before/target evidence contract and source rules for the known failure mechanisms. Visual acceptance requires comparable Studio views, not metadata or source inspection.

### F2 — durable docs leaked old release numbers into current guidance

**Severity: P1 process.**

Active/durable documents repeatedly named v0.6.1 as the current presentation/tooling/evidence release, even after v0.6.2 merged. Examples included architecture, homes, UI/UX, data model, tooling, production engineering, world-content pipeline, playtesting and visual-quality evidence copy.

**Action:** durable rules become version-neutral where possible. Version-specific requirements move into the v0.6.3 roadmap/acceptance/spec/plan.

### F3 — 0.6.2 visual evidence was left NOT RUN despite post-merge screenshots now existing

**Severity: P1 evidence honesty.**

The merged v0.6.2 acceptance record says Studio visual rows were NOT RUN. On 11 August the user supplied Studio screenshots of the v0.6.2 experience. Those screenshots are evidence and must not be ignored simply because they arrived after merge.

**Action:** preserve the automated PASS history but record a post-merge visual review as FAIL for the relevant art/composition rows. The screenshots become the qualitative before baseline for v0.6.3. They do not retroactively alter source/build evidence.

### F4 — “recognisable native part” was still too permissive

**Severity: P0 visual architecture.**

The docs correctly said native parts are allowed when convincing, but did not forbid several concrete failure recipes strongly enough:

- one enormous flat/slab roof as the dominant home/civic silhouette;
- window-as-bright-flat-rectangle;
- naked Neon/yellow sphere as ordinary practical lighting;
- isolated coloured platform as a destination cue;
- repeated house recipes over an undifferentiated flat plane;
- evenly scattered single-tree/single-prop dressing.

**Action:** add explicit failure rules and production architectural vocabulary to art direction, visual quality, homes, village and world-content guidance.

### F5 — neighbourhood identity was specified but not proven from screenshots

**Severity: P1 product.**

The four neighbourhood descriptions are conceptually distinct, but the elevated v0.6.2 screenshot reads predominantly as one continuous green plane with repeated plot patterns.

**Action:** v0.6.3 acceptance requires screenshot-level differentiation through path shape, terrain/elevation, planting, fences/hedges, clustered props and outlook.

### F6 — ordinary lighting was visually behaving like magic

**Severity: P1 art direction.**

The art contract says glow belongs mainly to magic/active feedback, but the screenshots show bright yellow spheres across ordinary civic/home spaces.

**Action:** practical light sources require fixture geometry with bounded warm light. Portal/fantasy glow remains the contrast layer.

### F7 — concept/reference intent needs an explicit evidence boundary

**Severity: P1 evidence.**

The generated TinyWorld concept board is highly useful as an art-direction benchmark but is not a screenshot of the actual Roblox build.

**Action:** documentation may name it as an aspirational target/reference only. It can never satisfy a Studio/device evidence row.

### F8 — 0.7.0 remains reserved

**Severity: guardrail.**

The family/girls review remains the intended source of v0.7.0 scope.

**Action:** v0.6.3 is inserted before v0.7.0. It must not consume guessed family-review features. It fixes the rendered visual foundation only.
