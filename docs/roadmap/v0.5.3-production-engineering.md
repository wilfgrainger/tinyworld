# v0.5.3 Production Engineering Foundation roadmap

v0.5.3 is the current engineering/release foundation: product version 0.5.3,
release name **Production Engineering Foundation**, profile schema 10, Rojo
7.7.0, and artifact `TinyWorld-v0.5.3.rbxlx`. It does not replace the v0.5.2
Village Soul product and presentation acceptance record.

## Sequenced phases

1. **Discovery and inventory.** Record the Git, Roblox, and
   Git-declared/Roblox-hosted state boundary; inventory real owners, assets,
   places, packages, and DataStore needs before automating them.
2. **Reproducible build.** Keep `default.project.json` as the Rojo boundary;
   validate the release contract and produce the place artifact locally and in
   credential-free CI.
3. **Release metadata.** Produce `dist/release.json` with the commit, branch,
   UTC timestamp, tool/config identity, artifact name, and SHA-256.
4. **DEV Open Cloud deployment — later.** Only after a configured DEV target,
   inventory, DEV-only credential, and explicit deployment design; v0.5.3 does
   not publish a DEV place.
5. **Runtime and multiplayer evidence — later.** Record Studio one-player and
   Server & Clients evidence against the built artifact; add automation only
   when it can prove the intended runtime behavior.
6. **Explicit LIVE promotion — later.** Require a separately configured LIVE
   identity, scoped credential, approved artifact, DataStore safety review, and
   a deliberate human promotion action. It is never an incidental CI or Codex
   operation.
7. **Asset/package governance and mature operations — later.** Govern asset
   IDs, package changes, source/licensing records, rollback, observability,
   approvals, and operational runbooks from the verified inventory.

Only phases 1–3 are implemented by v0.5.3. The later phases are gates, not
claims that DEV or LIVE infrastructure exists. Record actual evidence in the
[v0.5.3 acceptance checklist](../releases/v0.5.3/acceptance.md) and use the
[production engineering authority](../engineering/production-engineering.md)
for operating rules.
