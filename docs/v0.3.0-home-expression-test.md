# TinyWorld v0.3.0 home expression test

v0.3.0 turns the first functional home into a small authored expression space.
The slice adds free style choice, a six-piece fair collection, readable room
zones, visible decoration, and an owner-only showcase action. It does not add
paid items, random rewards, combat power, or unrestricted placement.

## Studio route

1. Start Play from the current Rojo-synced place. Confirm the HUD reads
   `TINYWORLD | v0.3.0 HOMES`, retains the four functional home-item count, and
   shows a style plus `Decor 0/6` or the saved collection count.
2. At the village **HOME STYLE** board, use **Change Home Style**. Confirm the
   style cycles Meadow → Harbor → Sunset → Meadow, the HUD updates, and the
   owned plot rebuilds with a matching exterior accent and interior banner.
3. At **HOME GALLERY**, collect the next affordable piece. Confirm a direct
   message, the HUD décor count, and a named visible object inside the owned
   home. Confirm a duplicate cannot be collected.
4. Collect/craft a material-backed piece after earning the relevant Meadow
   Seed, Seashell, or Wood Token. Confirm the resource is deducted exactly once
   and the object remains after the plot rebuilds.
5. Enter the owned home and use the **Showcase Home** plaque. Confirm the
   showcase count increases and the message names the selected style. A
   non-owner must not be able to increment it.
6. Stop and rejoin. Confirm the selected style, décor objects/count, and
   showcase count persist. Inspect Output and separate DataStore queue/session
   warnings from red source/runtime errors.

### Physical item invariant

The HUD is not enough to prove an item. Inspect the plot's **Item Chest**:
every non-empty Carrot, Sugar Crystal, Meadow Seed, Seashell, or Wood Token
inventory must appear as a named, count-labelled physical object on the chest.
Use **View Items** as the owner and confirm the popup lists the same contents;
a visitor cannot read another player's chest.

Plant, water, and harvest a carrot. The garden bed must visibly change from
sprouts to a labelled `CARROT READY` object and then clear when harvested; the
harvested carrot must appear in the Item Chest as well as the reward popup.

The same rule applies to every current item path: daily Carrots, portal Sugar
Crystals/Meadow Seeds, living-world Meadow Seeds/Seashells/Wood Tokens, and
trade receipts all sync the Item Chest and name the received item in the
on-screen message. The courier parcel, Tiny Bike, home essentials, home décor,
and portal collectibles are already physical world objects rather than HUD
claims.

## Evidence boundary

The source rules, migration tests, compilation, guards, and Rojo build prove
the bounded contract. A single Rojo-synced Studio client proves the visible
style/collection/showcase route, physical item affordances, and a rejoin
attempt. Two-client visitor comprehension, published-place parity, scale,
persistence across servers, and family/device desirability remain separate
evidence gates. If a Studio run cannot reach a garden or plot interaction
without a temporary movement aid, record that dependency rather than treating
a HUD value as visual proof.
